# Decision log

Locked decisions with rationale. Reversing any of these requires an ADR — the spec's amendment door (spec 5.5) — not a hallway conversation. `[open]` marks the ones still gated on outside parties.

## Product & market

- **D1 — Real money from day one, developed entirely on test rails first.** Solana devnet USDC + onramp sandbox cards until the compliance gate opens; the code path is the real-money code path from the first commit. *Why:* retrofitting money-grade correctness is how challengers die.
- **D2 — USA-only at launch; KYC rides the onramp.** Plus our own sanctions screening on withdrawals. *Why:* one hard jurisdiction done properly beats three done vaguely.
- **D3 — Mechanism: vote-share scalar trading, not parimutuel.** YES/NO shares trade in cents via CPMM over complete sets (~1% fee, prices sum to $1); each share redeems at the final vote percentage. *Why:* it's 's actual mechanism (reverse-engineered from the walkthrough), it's fully collateralized by construction, sell-anytime, zero house trading risk.
- **D4 — Vote-to-trade gate with the two-part vote** (side + crowd guess) and a **published scoring formula** (75% accuracy kernel / 25% majority match; tie at exactly 50.00% counts both sides as winners) feeding EWMA reputation. *Why:* their opacity is our opening; accuracy-weighting rewards crowd-reading. (Amended R2: scoring is *not* the bag-voting defense — the §3.4 eligibility stack is; see D21.)
- **D5 — Voter rewards are points/rep only at launch — no cash for voting.** *Why:* keeps the vote layer outside the money system, kills pay-per-vote sybil economics, legally simpler.
- **D6 — Everything public:** activity tape, top holders, sequential vote numbers. *Why:* transparency is core to the category's culture; hiding it reads as rigged.
- **D7 — Cadence: curated daily flagships + hourly flash markets,** genAI video per market (hero tier: text-to-video; flash tier: templated Remotion). *Why:* cadence is the loudest visible superiority, and only automated video makes it affordable.
- **D8 — Fees: ~1% on trades, withdrawals at network cost, no settlement rake.** *Why:* match their observed cost, beat their disclosure.

## Architecture

- **D9 — Rust monolith** (Axum + Tokio + SQLx + Postgres + Redis + NATS), **state-primary with transactional outbox + append-only domain-event log** (amended R1: not an event-sourced write model — state is authoritative, events feed projections/audit), CQRS-lite. One deployable. *Why:* correctness tooling and one operational surface; microservices solve a team-scale problem we don't have.
- **D10 — Solana is a USDC rail only.** Fully custodial internal double-entry ledger; chain touched at deposit/withdraw exclusively. *Why:* sub-second UX and simple invariants; on-chain game logic buys nothing here.
- **D11 — Comms: RPC in, WebSocket out, no polling.** *Why:* push-authoritative server keeps perceived latency sub-300ms and makes the tape/tally UX live by default.
- **D12 — Clean architecture with mechanically enforced dependency rule** (domain / application / adapters / main crates), SOLID, newtypes for every quantity, 100% line coverage on the money core enforced on stable CI + branch coverage on a nightly job + ≥90% mutation kill via a JSON-computed gate (amended R1: stable cargo-llvm-cov cannot gate branches), ≥90% ratcheted elsewhere. *Why:* an untested branch in the money core is a solvency bug.
- **D13 — Outcomes are first-class rows; ledger is append-only double-entry with account classes; deposits dedupe on chain signature; all idempotency via unique keys.** (spec 5.6.) Amended R1: internal accounts (`user/pool/fees/house/escrow`) are never negative; one `external` contra account represents the outside world so deposits/withdrawals/genesis are representable; two currencies (`usdc`, `usdc_credit`) from day one; sum-zero DB trigger is Phase-1 blocking before any write adapter. *Why:* multi-option generality and crash-safe money jobs fall out of the schema instead of being bolted on.

## Distribution & agents

- **D14 — iMessage-first distribution, Sendblue sandbox now.** Inbound-first with up to 10 verified tester contacts (free). Production channels sit behind one `ChannelPort`; Apple Messages for Business is pursued but **[open]** on Apple approving a wagering brand.
- **D15 — Conversation service: Python FastAPI + LangGraph, and no PydanticAI.** Plain Pydantic + `.with_structured_output()` + one retry; schemas centralized in `schemas.py`, API models generated from the core's OpenAPI. *Why:* one orchestration framework; PydanticAI's core value (validated outputs + retries) is already covered.
- **D16 — The money corridor is agent-free, confirmation is lexical, and votes are inside the corridor.** (Amended R1.) One execute node (`POST /trades` / `POST /votes`, idempotency-keyed, run_id-chained) behind deterministic gates: extractor → core-computed preview → 2-min pending action (kind trade|vote) → a **pre-router lexical confirm/cancel gate on raw inbound text** (allowlists; any other text auto-cancels and re-routes). Graph runs are single-flight per thread_id; webhooks dedupe on (channel, msg_id). LLMs never compute numbers, never authorize execution; composer numbers are injected and guard-checked; proactive broadcasts are template-only. *Why:* a metaprompt regression or router misroute must not be able to move money, cast oracle votes, or spam users — at worst it produces a preview.
- **D17 — Model policy:** gpt-4o-mini pinned per node at launch, temp 0 on router/extractors, versioned metaprompts. *Why:* cheap, fast, and structured-output-reliable; upgrade per-node when evals justify it.
- **D18 — Record every graph run** to `agent_runs`/`agent_steps` in our Postgres (rendered prompts, state snapshots, required rationale field, causal chain run → pending action → trade → ledger txn), plus self-hosted Langfuse and OTel traces spanning webhook → ledger. *Why:* debugging record and audit record; chat that moves money must be reconstructible; self-hosted because traces contain phone numbers.

## Verification & ops

- **D19 — The 2,000-agent swarm is the release gate.** Public-API-only, real sandbox rails, seeded/replayable, invariant suite + chaos knobs, SLOs: p95 trade < 300ms, p99 resolve-to-paid < 1s, WS < 100ms. Smoke swarm on every merge.
- **D20 — Configure-everything control plane:** DB-backed versioned dynamic config, hot-propagated; kill switches for trading/deposits/withdrawals; RBAC'd admin with full audit trail.

- **D21 — The vote-oracle minimum integrity bar ships with the core loop, not after it** (R1, anti-void rules added R2). Launch-blocking for any real-money resolution: unique verified phone, device fingerprinting, per-market vote velocity, new-account friction near close, and a positive `min_votes_to_resolve` threshold. **Anti-void rules so the void is not itself gameable:** auto-void only when participation < threshold *and* open interest < a configured floor; above the OI floor → one voting-window extension then curator decision; suppression/padding near the threshold feeds the anomaly sweep. Voids settle by **current-state neutral redemption from escrow** (both sides at 50¢ through the standard settlement path — historical-replay refunds can debit users who already withdrew and are not non-negativity-safe; R3); `voided` is a first-class lifecycle state. **ADR (P1R1/P1R2):** the "one voting-window extension" leg of the anti-void rules is deliberately deferred — the Phase 1 curator path for a thin-but-high-OI market is `NeedsCuratorDecision` → admin resolve/void via the conservation-checked settlement; `ExtendCloseOnce` (+ `extension_used` persistence) ships with the curation dashboard in Phase 5. A written vote-oracle threat model is a launch artifact. *Why:* the vote is the oracle; a thin or sybil-controlled electorate is insolvency-by-design — and a naïve void rule would hand losers a refund button.
- **D22 — During the hidden-tally window, ALL trading freezes — both sides** (amended R2, supersedes the R1 buys-only rule). Window length per tier (10 min daily / 2 min flash, config). *Why:* hiding the oracle while either side of the book is open gives vote-controllers a last-look (buy-side accumulation or informed dumping into the house LP). A short quiet close into sub-second resolution is the clean mechanism.
- **D23 — LP seed is managed as adverse-selection risk with an automatic kill-switch** (R1). Expected-loss model before real money; dynamic per-tier seed config; auto-pause on realized LP PnL threshold. *Why:* informed/manipulative flow drains seeds systematically; "marketing cost" needs a circuit breaker.
