## 0. Scope

**In:** withdrawal pipeline (hold-first; persisted three-dimension state machine; generalized `outbound_payments` + send-attempt lineage; dual control), deposit machine (ALTERed `deposits` authority; observation ≠ availability via `DepositSuspense`; source-locked refunds), bonus credits (grant lots; **provisional fees finalizing at Paid**; segregated `BonusReserve`; append-only fee allocations), referrals (server codes; `PhoneVerification` binds), KYC/sanctions/geo (allowlist; result algebra; egress split), AML at-request + sweep, statuses + responsible gaming, SLO gates (lib constants + pinned n_min + 2k release profile), reconciliation (signed formula), alerting (incident lifecycle), fee override with a drift predicate that actually sees it, config catalog + command matrix (tables below), invariant extensions.

**Out (post-beta / user-owned):** mainnet rails, production observability backends, real KYC/sanctions vendors, marketing surfaces. **Deferred by decision:** credit-funded trading.

## 1. Design decisions

### D31 — Withdrawal pipeline
- **Authority:** ALTER the 0001 `withdrawals` table. Persisted dimensions (codex NEW-M3): coarse `status queued|risk_hold|sent|settled|denied|failed` PLUS explicit CHECKed columns `review_state screening|review_required|approval_proposed|approved` and `send_state unsent|sending|broadcast|finalized|definitive_failed|unknown`, with impossible-combination constraints and a **published transition table** (in `docs/copy/ops.md`, W1-owned, listing every CAS source→target with its coupled ledger txn/audit/event/outbox). Columns: `hold_tx_id` (NOT NULL post-queue), `release_tx_id` XOR `settle_tx_id`, `request_fingerprint`, `risk_reasons jsonb` (snapshot), `requested_at/decided_at/sent_at/settled_at`. Legacy `txn_id` migrated to `hold_tx_id` where derivable, else quarantined by 0011 backfill rules; legacy `chain_sig` becomes a reference to the finalized attempt. Satellites: `withdrawal_events`, `money_command_proposals` (the generic dual-control authority — see command matrix). **The complete coarse × review × send combination table (legal states, hold/release/settle nullability, outbound-payment/attempt existence, every CAS authority, failure/retry edges, legacy mappings) is a 7.0a deliverable authored BEFORE 0011 — the migration CHECKs and W1's ops.md section both derive from that one table** (codex-p7r3 M1).
- **Outbound rails are generalized (grok B1 / codex NEW-M1):** `outbound_payments(subject withdrawal|deposit_refund, subject_id, dest, amount, …)` owns the send machinery for both withdrawals and deposit refunds. `outbound_send_attempts`: lease under row lock; **immutable signed tx bytes + signature persisted BEFORE broadcast**; monotone attempt number; `replaces_attempt_id`; `last_valid_block_height`; at most one prepared/broadcast/unknown attempt; only ever rebroadcast the persisted bytes while `unknown`; **definitive-failed requires an observed finalized height > last_valid AND signature absence from the pinned quorum source** (codex NEW-M2); `unknown` keeps funds encumbered and pages. Invariants: attempts 1:N per payment; ≤1 finalized attempt; exactly one finalized payment fact per settled payment.
- **Request protocol (codex NEW-B3 ordering):** (1) **persisted hit+fingerprint lookup FIRST** — fingerprint = immutable client intent only `(user, amount_micro, canonical dest)`; hit ⇒ original receipt (incl. persisted replay-stable refusal receipts) or 409 on fingerprint mismatch; (2) on miss: remote screenings with NO locks (geo/sanctions/KYC results persisted as separate facts with `checked_at/expires_at/policy_version`); (3) begin; `serialize_key` recheck; (4) `lock_user` (class-2, user before any money authority, never market locks); (5) revalidate under lock: `users.status`, self-exclusion, `pause_withdrawals`, KYC tier, geo/sanctions freshness, open AML flags; (6) auto-collect `min(cash, Σ open receivables)` via the shared collection routine; (7) available check; limits (below); (8) hold `User → Withheld` + insert + events; commit. Remote error ⇒ typed refusal, no hold, persisted for replay.
- **Limits (codex NEW-B4):** daily window = Σ over rows with `requested_at` in the rolling 24h UTC window in **all states except `denied` and definitive-failed** (settled still counts). Same rule for per-dest and hot-wallet caps, under the user/cap lock. Per-tx min ≥ dust floor.
- **Risk queue:** enter `screening`; auto-approve iff amount < `withdraw_auto_approve_micro` AND sanctions Clear AND no open AML flag AND dest is warm. **Dest warmth (grok M2):** requires **settled** cumulative to that dest ≥ `dest_warm_floor_micro` AND first-settle age ≥ `dest_warm_age_hours`; dust never warms; dest shared by ≥2 users is never warm; refund/return-to-source dests never enter the warm set. **Tighten-only (grok M4):** `risk_reasons` snapshot at request; decision/send applies union(snapshot, current) toward more review — a raised auto-approve threshold, warmed dest, or cleared flag never auto-approves an already-`review_required` row; kill switches and compliance checks always apply current values. Manual approve = finance (below-threshold single-finance is a named capped exception, boundary-tested); ≥ `withdraw_dual_control_micro` = full proposal protocol. AML/sanctions-flagged rows need two-person clearance. Deny reverses the hold with reason. Stuck rows past SLA page.
- **Send + settle:** claim attempt under row lock + lien recheck; receipt verification = signature, mint, source, dest token account, exact delta, `finalized` commitment; settle = `Withheld(-A) → External(+A)` keyed `withdraw-settle:<id>` + status + event + `withdrawal_settled` notification in one commit. **Platform absorbs SOL gas; full USDC amount delivered**; SOL treasury reconciles separately, non-USDC. Dest pubkey-validated + confirm-echo, canonicalized into the fingerprint. **Non-landing proof is an executable predicate (codex-p7r3 M2):** definitive-failed requires, from **2-of-3 independent archival RPC endpoints** (the pinned quorum), finalized block-height reads > `last_valid_block_height` AND signature-history absence (pruned-history ⇒ `unknown`, never `failed`); any disagreement or timeout ⇒ `unknown`; the evidence (endpoints, heights, lookups) is persisted on the attempt. **Immutable rail identity (codex-p7r3 M3):** cluster genesis hash, RPC endpoint set, USDC mint pubkey, decimals (6), treasury owner + token account, commitment level, and the deposit-depth interpretation are one startup-validated config, fingerprinted into every observation and outbound payment; wrong-cluster/mint/decimals/source tests required. Deposit `deposit_confirmations` and withdrawal `finalized` are the SAME finality contract: depth is measured against finalized roots.
- **Withheld** = new non-external `OwnerType` singleton per currency. Identity 3 extends; D27 numbering untouched. New identities, stated in full (codex-p7r3 m3): (a) `balance(Withheld,usdc) = Σ` amounts of rows holding an active hold (unsent or sent-unsettled); (b) every accepted row has exactly one exact `User → Withheld` hold; (c) every terminal row has exactly one exact reversal XOR one exact `Withheld → External` settlement leg, never both; (d) send attempts are 1:N per outbound payment with ≤1 finalized attempt, and each settled payment pairs 1:1 with exactly one finalized payment fact/signature and its external leg; (e) no duplicate terminal effect under replay.
- **Unwind interaction (codex NEW-B6 algorithm):** unwind = lock-free participant enumeration → **sorted user-lock acquisition** → market/unwind row lock → re-enumeration (new participant ⇒ release, retry) → cancel unsent withdrawals + release-then-collect + reversal under the stable lock set. `UnwindTx` += `UserLockGuard`. Sent-but-unsettled amounts are outside the lien; shortfall opens a receivable. **Payout uses the same protection (codex-p7r3 B5):** `ResolveTx` += `UserLockGuard`; payout-recipient algorithm = lock-free holder enumeration → sorted user locks → market lock → holder re-enumeration/retry → payout + oldest-first receivable collection in the same tx; raced against PlaceTrade, withdraw request, deposit admission, remedial, unwind. If the lock cost breaks the 1s SLO on a 1k-voter book, payout cash is kept in a per-user encumbrance authority and released/collected on the user's next `lock_user` tx — never exposed unlocked.
- Chaos: `withdraw_send_crash`, kill-between-hold-and-decision, admit∥refund race, concurrent withdraw+trade+deposit+unwind Pg contracts.

### D32 — Deposit machine + bonus credits
- **Canonical authority = ALTERed `deposits` (codex NEW-M1):** states `observed_finalized → admission_pending → admitted | compliance_hold`, with **reevaluation edges** (codex-p7r3 M9): `compliance_hold → admission_pending` on fresh facts (KYC renewal, geo/sanctions re-Clear, limit change) and manual `compliance_hold → admitted` only via the command matrix (compliance-decision event + admin_actions both written); `compliance_hold → refund_approved → refund_sending → refunded` remains the terminal alternative; hold reason/version history preserved; release raced against refund approval/send. `source_address` captured from chain; `suspense_tx_id`; `admit_tx_id` XOR `refund_tx_id` (CHECK once terminal); row-lock + CAS. **Legacy-row rule (codex-p7r3 B6):** 0011 grandfathers pre-existing `credited` rows as `admitted_legacy` (identity-4 carve-out documented; `txn_id → admit_tx_id` mapping; no suspense leg exists and none is invented); `seen|confirmed` rows migrate to `observed_finalized`/`admission_pending` only if their observation can be re-derived, else quarantined; `user_id` may be null for unmatched finalized inflows (suspense-held, compliance-paged); upgrade tests cover credited/confirmed/seen rows. Every finalized inflow at `deposit_confirmations` depth books `External → DepositSuspense` — always. Admission (KYC ≥ tier, geo Clear, sanctions Clear, `pause_deposits` off, user deposit limit) = `DepositSuspense → User` + auto-collect, one tx, CAS'd; machine admissions write a **compliance-decision domain event, never `admin_actions`** (codex NEW-m3); manual overrides write both with AdminContext. **Refund is not a withdrawal:** dest **= `source_address`**, settle `DepositSuspense → External` keyed `deposit-refund:<id>` via `outbound_payments(subject=deposit_refund)`; omnibus/exchange sources require compliance review. Suspense invariant: `balance(DepositSuspense) = Σ` non-terminal observation liabilities; identity-4 extension names observation legs explicitly. Post-credit deeper reorg = accepted house loss (ops.md). Onramp/KYC webhooks: signed, user from our records, durable inbox with hash algebra.
- **Credits:** grant = `House(UsdcCredit) → User(UsdcCredit)`; immutable lots stamping `(source, amount, granted_at, grant_class + redemption promise, policy_version)` — a `bonus_structure=real_money|sweeps` change affects only future lots; existing lots honor their stamp; the change proposal previews affected liability and refuses stranding transitions (codex NEW-M9). **Fee progress:** append-only `credit_fee_allocations(trade_id, lot_id, split_seq, amount_micro, kind allocated|finalized|reversed, source_allocation_id, idempotency_key)` with net-per-trade ≤ that trade's actual `legs.fee` credit (**never notional×bps** — grok m1) and net-per-lot ≤ requirement; deterministic oldest-first split. **Allocation algebra (codex-p7r3 M5):** unique `(trade_id, lot_id, split_seq)` per `allocated` fact; ≤1 terminal child per source allocation (`finalized` XOR `reversed`, each naming its exact live source, unique on it); `finalized` MOVES the same amount from provisional to finalized — it never adds economic progress; reversal never exceeds its source. Lock order: `user → sorted lots → BonusReserve/accounts`; allocation facts, both ledger txns, and `converted_at` in one tx. Duplicate-finalize, finalize-vs-reverse, split, and convert-vs-unwind races are Pg-tested. **Allocations are provisional until the fee's market reaches `Paid`** (codex NEW-B1); conversion draws only on finalized allocations. Convert = two ledger txns in one DB tx (`User credit → House credit` retire + `BonusReserve(Usdc) → User(Usdc)` pay) under lot row lock, namespaced keys, `converted_at` in the same tx, replay returns original tx ids; **convert-then-collect inside the same `lock_user` tx**. **`BonusReserve`** = new non-negative singleton class, funded only by dual-control `House → BonusReserve`; only conversion debits it. **Reserve-at-grant (codex-p7r3 B2):** the coverage invariant is `BonusReserve ≥ Σ remaining cash redemption promise of every unconverted real_money lot` — lot issuance and capacity reservation are atomic (per-lot encumbrance); capacity releases only on conversion, a stamped-promise expiry/cancellation, or an exact correction command; qualified liability is a reporting subset, never the solvency floor; an earned conversion can therefore never fail. Grant∥top-up∥fee-finalization races at zero/near-zero reserve are Pg-tested. **D30 stands unchanged: unwind is never legal from `Paid`** (grok-p7r3 M3) — so a convert can never precede an unwind on the same market by construction. **Voided-market fees are forfeited for bonus progress**: provisional allocations on a Voided book never finalize and are not compensated (fees themselves return to users only via a D30 unwind, which reverses the provisional allocation rows too); W3 must NOT finalize on Voided "to be helpful". Converted lots never reopen. Allocation **finalization** happens in the resolve-to-Paid tx; the **convert itself fires lazily on that user's next `lock_user` transaction** (still convert-then-collect) so a 1k-voter payout tx never also debits BonusReserve for every qualifier (grok-p7r3 m1). Platform-absorbed SOL gas is bounded opex: the USDC hot-wallet daily cap bounds attempt count (cap / per-tx min); named in ops.md as accepted house cost (grok-p7r3 m3).
- **Referral:** server-issued codes; binds on **`PhoneVerification`** (port + named sandbox adapter + public challenge/verify routes, staging-two-factor armed like the faucet; `phone_verifications` table with **`unique` verified normalized-number HMAC** (HMAC key-version column for rotation), one active challenge per number/account, atomic attempt/rate-limit consumption, `verified_at`, provider ref, durable account bind; grant requires the fact; linked-but-unverified ⇒ grant 0; two-accounts-one-number race proves only one becomes grant-eligible — codex-p7r3 M10), device HMAC, first funding instrument, dest wallet; referrer≠referee on all keys; both legs on referee's first Paid market ≥ `referral_min_notional_micro`; mint caps; `feature_referrals` two-phase, refuses `true` until binds exist.

### D33 — KYC / sanctions / geo (normative, self-contained)
- **Geo = versioned US-state allowlist** (counsel-owned content, shipped as the `region_allowset` config value with monotonically increasing `region_allowset_version`): progress requires country US AND state ∈ allowset; unknown region, missing policy, missing client IP, untrusted proxy chain, or resolver error ⇒ deny money mutations. IP via the existing `TRUSTED_PROXY_CIDRS` rule verbatim; converse passes the **user's** KYC-derived region, never the box IP.
- **Result algebra:** `Clear{checked_at, expires_at, policy_version} | Hit | Indeterminate`; only fresh Clear progresses; Hit/Indeterminate hold; re-screen at the send boundary when aged past TTL. KYC: `users.kyc_tier` stays `int` (0=none/1=basic/2=full documented); `kyc_events` append-only with validity horizon and downgrade/revocation; provider webhooks authenticated + inboxed (signature verified, user from OUR records, `unique(provider,event_id)`, payload hash: same key+hash → original result, different hash → typed conflict + page). Sandbox KYC-completion route is staging-two-factor gated like the faucet.
- **Enforcement (fail-closed):** signup grant, deposit admission, PlaceTrade, CastVote, withdraw request; sanctions additionally at first trade; a sanctions Hit = dual-control compliance hold on the account.

### D34 — Statuses, responsible gaming, egress split
- AML at request AND swept: per-user + per-dest velocity over deposits AND withdrawals incl. converted cash-outs; **structuring counts only legs with amount in `[aml_structuring_floor_micro, aml_structuring_threshold_micro)`** (codex-p7r4 B1 — the floor makes the band executable: $25 onramp dust is below the $100 floor and never counts) — N such legs per user or per dest within the window flags; the e2e proves four $25 deposits do not flag while four $499 withdrawals do and three do not; open flag blocks auto-approve and send; dual-control clear.
- `users.status` (`active|shadow_limited|banned`) read under `lock_user` in every money mutation; next-request semantics; drain-safe; not a config key. Ban = dual-control (matrix). Shadow-limit = single ops; caps from config seeded to the **published tier-0 numbers**; homogeneous errors (no ShadowLimited code, no echoed cap); author-visible comments read `visible` to self; no public WS emission; no self-profile status; shadow withdrawals always `risk_hold`. **Self-exclusion (normative):** user-initiated, effective immediately, irreversible for the stamped cooling-off interval, lift only via the command matrix after expiry; blocks grants/trades/deposits/withdrawals except the settled-dest return path (egress table). **User deposit limits:** self-set, enforced at admission, lowering immediate, raising takes effect after a 24h delay (no-instant-raise).
- **Egress split (grok B2):** `banned`/sanctions-`Hit` ⇒ NO send; freeze in place; dual-control counsel-shaped license only (dest never user-picked; Hit source never auto-refunds). Admission-refused + Clear ⇒ source-locked refund (D32). Self-exclusion + Clear ⇒ D31 withdrawal to a previously-**settled** dest or the observation source; new dest = `risk_hold`.

### D35 — SLO gates, reconciliation, alerting
- Lib constants: targets 300ms/1s/100ms AND **per-profile minimum-series contracts derived from each profile's manifest** (codex-p7r3 m2): the expected trade/close-to-paid/ws series sizes are computed from the roster/market plan and asserted as `observed ≥ expected` — exact integers per profile, not one shared constant; the ≥50%-convoy-2xx assertion is separate from series thinness. Smoke and the 2k profile each carry their own contract; the 2k profile must include one ≥1k-voter book. Convoy 2xx are **inside** the gated trade series. **`close-to-paid` = authoritative Closed transition → committed Paid event, minus only the named risk-hold interval — never `tally_hidden_at`** (codex NEW-M5); deterministic unit trace asserts the arithmetic. Timer = HTTP send → 2xx per action. `SLO_ENFORCE=0` grep deleted. Release artifact = gated smoke AND the pinned 2k profile (10% money path incl. withdrawals, close spike, chaos-healed; chaos-delay legs excluded by name). Thin series fail.
- **Reconciliation (signed, one pinned finalized chain cut — codex-p7r3 M4):** `wallet_balance@finalized_cut = −balance(External)@db_cut − Σ(outbound finalized on-chain but not yet ledger-settled) + Σ(inbound finalized-observed but not yet ledger-booked)`; **broadcast/unknown attempts are NOT subtracted** — they are reported separately as exposure, never as drift; the observation slot/status used in each term is persisted; only the residual pages at 1µ. Numeric example per state (dropped, confirmed-only, finalized-before-DB, replacement) in the e2e.
- **Alerter (normative):** durable alert outbox; incident key = detector+subject+episode; dedup within an open incident; at-least-once delivery; ack/resolve recorded; re-page on recurrence after recovery. Pages: invariant breach, reconciliation residual, AML flags, stuck rows (`send_state=unknown` past SLA, `review_state=screening` past SLA), reserve-coverage failure. `ChainBalance` + `Telemetry` ports: chain balance reads at the pinned cut; telemetry is a span/counter port with no-op prod default and recording fake.

### D36 — Fee override (normative, self-contained)
`fee_bps_override:{market_id}` is a **typed enum `inherit | override(bps)` with seed `inherit`** (codex-p7r3 M7 — unset is representable, revert = write `inherit`; the 20bp/5min delta baseline for the first override is the market's immutable pool stamp): finance+2P, bounds [10,200], delay per matrix; the write IS a generation bump writing `config_changes` so `preview_relevant_drift` fires for that market; `MarketFeeChanged` outbox/WS frame in the same tx. `preview_relevant_drift` and `FeeContext.base_bps` **read the override** (override replaces the pool stamp as base) — both code paths W3-owned via explicit 7.0a→W3 transfer. `expected_config_version` required on PlaceTrade (422 absent); converse carries it.
