## 1. Design decisions

### D24 — Config store (generation-serialized; durable two-phase proposals; full catalog)
Tables: `config_entries(key pk, value jsonb, updated_at)`; `config_generation(singleton pk check(singleton=1), generation, updated_by, updated_at)`; `config_generations(generation pk, applied_by, at)` + `config_changes(generation fk, key, old jsonb, new jsonb, primary key(generation, key), index(key, generation))` — one row **per changed key** in the patch tx (codex r3 NEW-1: a multi-key patch shares one generation); bounded hot history with a retention watermark: a preview generation older than the watermark makes `PlaceTrade` conservatively return `StaleConfig`, while emergency revert reads the archived immutable history; `config_change_proposals(id pk, idempotency_key unique namespaced, patch jsonb, patch_hash, base_generation, proposer_token_id, proposer_role, status(pending/confirmed/rejected/expired), expires_at, confirmer_token_id, resulting_generation, reason)`; `admin_actions` (D26).
**Write path:** `SetConfig` = typed patch over the whole prospective snapshot. Non-sensitive keys apply directly; **sensitive keys (fee, seeds, tier caps, flip window, integrity ppm/velocity, min_votes, hold threshold, voting pause) require the proposal flow**: proposer (finance or superadmin) creates the proposal row + audit atomically; confirmation requires `confirmer_token_id ≠ proposer_token_id` (schema-enforced; e2e: same token 403), locks the proposal row, then all applicable exclusive pause fences in canonical order, **then** the generation row, revalidates the complete prospective snapshot against current state (typed stale/conflict if base moved incompatibly), applies once, writes `config_changes`, audit, outbox wake — one tx. Proposals **expire** (default 15 min); either principal may reject (audited); after apply, `config_changes` retains `old` so an **emergency revert** is one new proposal pre-filled from history (same dual control — never a trading pause; ops.md forbids pause-as-config-hatch).
**Read path:** watch snapshot per process; single reconciler woken by the outbox cursor (events are wake-ups only), reloading wholesale when `config_generation` exceeds applied. Pg contracts: (a) writer B **blocks** behind writer A on the generation row (serialization proof); (b) a missed wake-up heals from the authoritative generation on the periodic tick.
**Catalog (complete; bounds enforced 422 at write; each key: apply-to class / role / max-delta):** `trade_fee_bps` [10,200] finance+2P Δ≤20bp/5min **new-market-only**; `min_fee_bps` [0,50] finance+2P; `discount_flip_window_secs` [600,86400] finance+2P; `position_cap_micro_by_tier` (each ≥ published tier table, monotone) finance+2P; `rep tier thresholds` (monotone) finance+2P; `rep_score_min_pot_micro` [0,10^9] finance+2P; `seed_micro per tier` ≥ `seed_floor_micro`, ≤2× prior finance+2P; `daily_seed_budget_micro` finance+2P; `hidden_window_secs` [60,900] < `open_secs` **live-immutable** finance+2P; `min_votes_to_resolve` ≥ published floor live-immutable finance+2P; `oi_floor_micro` [0,10^9] live-immutable finance+2P; `payout_hold_threshold_micro` [10^6, 10^10] live-immutable finance+2P; `sweep_delay_secs` [60,3600] ops; `vote velocity (max_votes_per_window/window)` bounds ±50% of published ops+2P; `integrity ppm knobs` (burst/young/device/subnet/coverage) ±20% of shipped defaults superadmin+2P; `cadence (flash_cadence_secs, daily_slots)` [900,86400]/[1,4] curator; `feature flags (flash_markets, comments, referrals)` ops; `trading_paused`/`market_paused:{id}` ops immediate; `voting_paused:{id}` superadmin+2P immediate w/ auto-expiry (D25); faucet caps finance immediate [≤ $1,000/call]; **`fee_discount_bp_by_tier` = published `[0,0,10,20,30]`** finance+2P next-trade, each entry ∈ [0, `trade_fee_bps`], monotone non-decreasing, Δ ≤ 10bp/5min per entry — the `min_fee_bps` floor applies to the **computed effective fee per tier** (`max(base − discount, min_fee)`, exactly the shipped `effective_fee` formula), never to the discount entries themselves, so the published seed validates (codex r4 NEW-1; grok r3 N9 — the wash 100-not-90 assertion is provable only against this vector); remedial-credit caps finance+2P [per-market ≤ $500 = 500_000_000 micro; daily house ≤ $2,000] (422 over). Attribute completeness (codex r3 carryover): every key above carries all four attributes — `min_fee_bps` [0,50] finance+2P next-trade Δ≤10bp/5min; rep tier thresholds monotone finance+2P next-trade Δ≤10%/proposal; `rep_score_min_pot_micro` [0,10^9] finance+2P next-trade Δ≤2×; `payout_hold_threshold_micro` Δ≤2×/proposal (absolute [10^6,10^10] as above); `daily_seed_budget_micro` [10^6,10^11] finance+2P new-market-only Δ≤2×/day; `sweep_delay_secs` ops immediate [60,3600] Δ≤2×; cadence curator immediate [900,86400]/[1,4] Δ one step; feature flags ops immediate (boolean — max-delta n/a); faucet caps finance immediate [≤$1,000] Δ≤2× (codex r4 catalog completeness: every key now carries all four attributes). Apply-to classes: **live-immutable** stamped on the market row at go-live (config affects later markets only; never rewrites a live `tally_hidden_at`/threshold); **next-trade** (caps, flip window — see D25a staleness); **new-market-only** (fee, seeds); **immediate-global** (pauses, flags).

### D25 — Kill switches (three fence namespaces; drain-safe; voting pause fenced AND expiring)
**Namespaces (advisory class 4):** `trading-global`, `trading-market:{id}`, `voting-market:{id}`. PlaceTrade takes the two **trading** fences; CastVote takes **only** `voting-market:{id}`; a trading pause can never delay votes.
**Drain-safety (codex r2 NEW-1):** shared fences are acquired **after** the existing user/market row locks, immediately before the first authoritative write, under a documented **one-way lock graph**: pause writers take only (proposal row → exclusive fences → generation row → config rows) and never any downstream trade/vote lock, so exclusive acquisition waits only on currently-writing holders, never on the queued convoy. Requests still queued on row locks hold **no** fence and observe the pause when they reach the fence point (typed 423). Convoy contract test: 2,000 queued writers; pause latency bounded by the in-flight writer set; queued writers 423; votes proceed throughout a trading pause.
**Trading pause:** ops role + reason; public `TradingPaused{market?}`/`TradingResumed` outbox→WS frames in the pause tx; resume forbidden inside `(tally_hidden_at, closes_at]`; ops.md: pause ≠ D22.
**Voting pause (grok r2 f2):** superadmin + **two-phase distinct principals** + reason + public `MarketVotingPaused` frame; **write forbidden once `now ≥ tally_hidden_at`** unless the same action voids; and the pause **auto-expires at `tally_hidden_at`** — CastVote's fence-point read treats a Live-set pause as void once the hidden window starts (no carry; the operator cannot freeze the final public tally and ride D22). E2E: set during Live → votes 423; at `tally_hidden_at` → votes 200 again without any admin action.
**Preview:** lock-free, best-effort snapshot check + `config_version` stamp; PlaceTrade authoritative at the fence point.
**Idempotency-replay precedence (codex r3 NEW-3), pinned:** `serialize_key` first; on a key HIT, compare the persisted canonical request fingerprint (market/user/action/amount/`expected_config_version`) and return the original receipt **without any pause or config check**; a fingerprint mismatch is a typed `409 IdempotencyConflict`. Only a key MISS proceeds to row locks → shared fences → authoritative pause/config reads → writes. Contracts: replay-after-pause, replay-after-relevant-drift, concurrent retry, same-key-different-payload — fake + Pg.
**Live voting-pause hardening (grok r3 NEW-3 residual, adopted):** while a `voting_paused` is in force during Live, PlaceTrade/Preview on that market also return 423 — the book never trades against a frozen tape. Auto-expiry at `tally_hidden_at` releases both (D22 restored exactly).

### D25a — Preview/execute coherence (market-relevant staleness only; no live repricing)
**There is no `reprice-market` in Phase 6** (grok r2 N3): pool `fee_bps` is stamped at creation and immutable for the market's life; `trade_fee_bps` config is new-market-only. Live-market fee changes are out of scope until real auth (Phase 7).
`TradePreview` stamps `config_version`, and the **public PlaceTrade contract carries `expected_config_version`** (codex r3 NEW-2): DTO + OpenAPI + converse pending action + the idempotency request fingerprint all include it; `adapters/src/http/dto/market.rs` and `routes/market.rs` are W1-owned for these fields. `PlaceTrade` returns `409 StaleConfig` **iff a preview-relevant field for THIS market and user changed** since that generation (checked via the `(key, generation)`-indexed `config_changes`): this user's effective position cap, the flip window when the pending action would flip, or **any effective-fee input for this user — `min_fee_bps` and `fee_discount_bp_by_tier` are in the market/user-relevant change set** (a lexical yes can never execute different fee economics than previewed). A global fee change (new-market-only) **never** 409s an existing book — e2e asserts place 200 at the old pool fee after a global fee change. Converse contract on 409: expire the pending, send a **new** preview, require a **new** lexical yes; never execute from the old pending; never re-loop the same version (grok r2 N8). E2E: flip-window churn does not 409 a non-flip buy.

### D26 — RBAC + audit (fail-closed matrix; atomic per mutation; saga-aware)
Capability matrix (single table in `routes/ops.rs`): every `/admin/**` route → capability set; roles are sets, no hierarchy; **dual-control endpoints additionally require distinct token ids** (proposals, unwind, voting pause, remedial credit, receivable write-off). Middleware: one fail-closed layer; `ADMIN_TOKENS_JSON` parsed at startup (reject empty/dup/malformed; SHA-256 digests; constant-time compare); legacy `ADMIN_TOKEN` + fallback removed in 6.0b (e2e scripts migrated); audit reads need `audit-read` (not curator); token digests redacted.
**Atomicity (codex r2 NEW-2):** every admin mutation's **single-transaction** effect carries its `audit_insert` in the same tx (AdvanceTx/ResolveTx/CommentTx/OpsTx… — `AuditWrite` role, behavior-tested placeholders from 6.0, no permissive defaults). **Multi-transaction admin effects are command-based (codex r3 NEW-4):** `POST /admin/drafts/{id}/publish_now` atomically inserts (idempotent publication command + audit row) into `publication_commands(id pk, draft_id unique where open, requested_by, status pending/executing/done/failed, lease_expires_at, attempts, result_market_id, idempotency_key unique)` and returns **202 + a status URL** (`GET /admin/drafts/{id}/publish_status`); the existing publisher tick consumes due commands FIRST (before cadence-due drafts) under its existing lease discipline — crash-after-authorize leaves a pending command that the next tick executes exactly once (recovery contract on fake + Pg). The audited fact is the authorization; stage effects remain saga-owned. Shared use cases take a typed `AdminContext` actor (Machine | Admin{token_id, role}); audit rows written only for Admin actors; machine paths (scheduler, publisher) unchanged — Phase 0–5 suites must stay green with Machine actors. Replay-job / re-run-fanout: durable idempotent command + audit in one tx; leased runners deliver. Failure-injection contracts (before effect / between effect and audit / at audit / at commit) on fake + Pg for every admin entry point.

### D27 — Invariants (six identities + receivables subledger; one snapshot)
Identities per currency: (1) per-tx sum-zero; (2) non-external accounts ≥ 0; (3) `−balance(External) = Σ(user ∪ pool ∪ fees ∪ house ∪ escrow)` — **cash only; receivables are NOT a ledger account class** (codex r2 NEW-3); (4) payment facts ↔ external legs 1:1; (5) per-market escrow history (seed + mints/burns + fees + payouts + reversals ⇒ 0) with `collateral_at_close` recorded in the resolution tx; (6) job idempotency (no duplicate terminal effects); (7) **receivables subledger reconciliation**: every open receivable traces to exactly one unwind reversal tx whose house leg equals the booked shortfall; `Σ open receivables = Σ house shortfall legs − collections − write-offs`.
`InvariantReadTx`: one `REPEATABLE READ, READ ONLY` Pg tx (statement timeout), fake clones state, as-of marker, wholly-before-or-after concurrency contract. `GET /admin/invariants` (ops); `--continuous` main flag; swarm calls it only in quiet segments.

### D28 — simswarm (outer harness; rings with pinned inequalities; versioned manifest/trace)
**Crate posture:** no internal crate deps (own wire DTOs + drift test vs `openapi.json`); HTTP construction confined to `simswarm/src/transport.rs` (deps-check extended); `check_dependency_rule.py` ALLOWED += simswarm(∅); coverage recipe `-p simswarm --fail-under-lines 100`; `Exec`/`Sleeper`/`Transport`/`Ticker` injected roles; thin bin.
**Determinism (codex r2 NEW-4):** a versioned **run manifest** (schema_version, code/decision version, scenario config, seed, agent/ring roster, RNG stream derivation rules) and **trace schema** pin the artifacts. Two artifact kinds: `PlannedOpportunity` — `(sim_tick, agent_or_ring, local_seq)` decision opportunities derivable with **no network** (the `--dry-run` output; byte-identical across runs by canonical JSON encoding, defined same-tick ordering incl. ring vector-action order, and counted RNG consumption); `DecidedAction` — live trace records per opportunity: market_view (canonical bytes + hash), decision, HTTP/WS outcome (normalized), retry classification (deterministic sim-tick rescheduling), WS gap/snapshot records (a gap's recovery snapshot becomes the next recorded view). Ring/persona state reconstructs from manifest + ordered trace alone; `--replay-log` rejects schema/config/code-version mismatches. Exit criterion 2 compares what dry-run can actually produce (PlannedOpportunity logs) and replay equality of DecidedActions.
**Personas + rings:** six personas for load; `Ring` = k agents sharing device HMAC / forwarded-for /24 / channel prefix, one decision fn returning `Vec<(agent, Action)>`. **Pinned efficacy inequalities (grok r2 N1 — written here so a red e2e cannot be "fixed" by weakening thresholds):**
- *Sybil fat pot:* honest baseline ≤ 15 votes; **aged** ring k ≥ 31, one device id + one /24, burst inside `[closes_at − 60s, closes_at)`, near-zero prior windows ⇒ `device_share = k/(k+15) ≥ 60%` AND `vote_burst > 2× prior` both fire ⇒ two signals ⇒ Flag. Requires pinned `DEVICE_HASH_SECRET` (non-empty), `TRUSTED_PROXY_CIDRS` covering swarm egress, pot ≥ pinned `PAYOUT_HOLD_THRESHOLD_MICRO = 500_000_000` (published $500).
- *Near-close proof market:* `FLASH_CLOSES_SECS = 720` (> 600s rule), 80/20 aged/young ⇒ aged vote 200, young 422. This market proves the age rule; the sybil market proves the flag — never one market for both.
- *Wash pair:* one member staging-rep-seeded ≥ 400_000 micro (tier 2) under the staging arm ⇒ assert the sell leg ledger fee = **100bp base, not 90bp** (anti-churn flip rule engaged); at tier 0 the assertion is vacuous (grok r2 N9).
- *Void-suppress vs threshold-pad:* run on two markets — suppress market with `oi_floor_micro` low (void branch), pad market with a **positive** pinned OI floor (forced-tally / NeedsCuratorDecision branch) so both D21 branches are distinctly asserted.
**Identity policy:** 80% aged (`created_at = now − 80d`) / 20% young; overrides ride the staging arm, audited; integrity profiles never zero `VOTE_MIN_ACCOUNT_AGE_SECS`.
**Roster isolation (grok r3 NEW-1 — holds at EVERY scale):** the sybil fat pot's voter set is the aged ring (k ≥ 31) plus **≤ 15** honest voters **in both smoke and the 2,000-agent profile** — the 2k load roster and the ≥1k-voter settlement hit only the convoy/lifecycle market. Every non-ring agent carries a **unique** `x-device-id` and a unique forwarded-for /24 (ring members share one of each), so the 1k-voter lifecycle book must assert **Pass (at most one signal)** while the fat pot asserts Flag — both assertions in the e2e; integrity ppm knobs are ±20% two-phase so a red run cannot be "fixed" by threshold surgery, and unsetting `DEVICE_HASH_SECRET`/`TRUSTED_PROXY_CIDRS` fails the pinned-env check.
**SLO:** p50/p95 trade-confirm (on 2xx; in-window 423s reported separately), p99 close→paid excluding configured hold, p95 WS delivery; `SLO_ENFORCE=0` printed; reports persisted.

### D30 — Unwind + remedial credit (one tx; receivables as facts; both dual-controlled)
**True unwind** legal only from `Voided` or flagged-`Resolving` pre-payout; **never from `Paid`**. **One transaction** (precedent: Phase 3 settles ~2k voters in one tx), namespaced reversal keys `unwind:<market>:<orig_entry_id>`, DB-unique `reversed_entry_id` lineage, `market_unwinds(market_id pk, unwind_key unique, stage, proposer/confirmer token ids, reason)` authority; dual control (propose superadmin / confirm finance, distinct token ids, ≥T delay, two audits). Enumerated: trade cash legs reversed; positions zeroed; complete sets burned; seed → house; **trade fees reversed to users**; hold cancelled; realizations compensating facts; **no EWMA rewrite**; assets tombstoned; outbox + WS frame.
**Shortfall accounting (codex r2 NEW-3, r3 NEW-5):** if a user's cash < their reversal debit, the reversal tx books the shortfall **house leg** (cash stays exact; identity 3 untouched) and opens a receivable in a **non-cash subledger**: authority `receivables(id pk, unwind_id fk, origin_reversal_tx_id fk, user, market, opened_micro)` (unique per user+unwind) plus append-only `receivable_movements(id pk, receivable_id fk, kind opened|collected|written_off, amount_micro, actor, audit_id, cash_tx_id nullable, idempotency_key unique)` — outstanding is **derived**, never overwritten; reconciliation is **per origin reversal transaction** (Σ opened for that tx = that tx's house shortfall legs), which is what identity 7 computes. Collection appends a movement + the cash tx (user → house) and is self-serve at deposit time (auto-collection). **Write-off is a single-principal economic transfer and therefore carries the full unwind-grade protocol (codex r4 NEW-2):** immutable proposal, finance/superadmin **distinct token ids**, ≥T delay, mandatory reason, two atomic audits, idempotent confirmation, per-write-off and daily caps in 0008; the confirmed command links the movement AND the compensating realization fact; it appears in D26's dual-control endpoint list; fake+Pg + RBAC e2e prove one principal cannot forgive a receivable. Collection/write-off use cases, routes, real fake impls, Pg impls are W2-owned (6.0a owns only the Unavailable placeholders — explicit transfer). **Voided-market unwind additionally reverses the already-committed neutral-payout transaction and its dust legs, with LP-PnL compensating realizations enumerated** (codex r3 carryover). **Withdrawal lien with auto-collection (grok r3 NEW-5):** deposits **auto-collect** `min(cash_after_deposit, Σ open receivables)` in the same tx; because no withdrawal use case exists until Phase 7 rails (codex r3 NEW-6), the guard ships as a `WithdrawalEligibility` application role + fake/Pg contracts (open receivable + zero cash ⇒ blocked; after auto-collection ⇒ clear) exposed read-only at `GET /admin/users/{id}/withdrawal_eligibility` — no phantom HTTP withdrawal surface. House-receivable outstanding is capped: past the named threshold new unwind confirms 422 and finance is paged. ops.md: void is terminal settlement; unwind-from-Voided means "void was the *wrong fraud decision*", never t0 cleanup.
**Remedial credit (grok r2 N2):** same control grade as unwind — dual control distinct token ids, ≥T delay, reason, two audits; per-market **and** daily house caps in 0008 (422 over); credits refused to accounts linked to either principal; honesty paragraph (not a refund, not PnL make-whole); e2e: finance alone 403, over-cap 422, `Paid` unwind still 409.
