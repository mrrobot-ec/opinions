VERDICT: BLOCKED

[B1] — The four-way wave is not file-disjoint at its contracts. Task 5.4 must compile against `DraftSpec` and `DraftEngine`, but Task 5.1 owns and may create both during the same wave; Task 5.2 says its active-job index may live in `0007b_content_seed.sql`, which Task 5.1 exclusively owns and the matrix labels data-only. The matrix also omits shared dependency manifests/lockfile, crate `lib.rs` files, `adapters/pg/{mod,store,rows}.rs`, central fake state/pending/commit machinery, application/adapters errors, WS/relay types, OpenAPI registration, renderer fixtures/fonts/palette assets, and the `justfile` gate it asks 5.0 to change.

FIX: Task 5.0 must freeze complete, final `DraftSpec`, `DraftEngine`, `Renderer`, content/video tx/factory, DTO, error, event, WS, persistence, and config signatures before the wave. Assign every omitted surface to 5.0 or one named owner, move the unique-job index into migration 0007, and reserve dependency/lockfile plus generated-artifact changes for serialized coordinator windows. Treat requests to change any frozen surface as a barriered plan revision, not merely an `ask` while other workers continue compiling.

[B2] — The proposed pre-wiring is not demonstrably compilable or coverage-clean. `StoreError` has no `NotImplemented`, Rust cannot wire loops to functions or traits whose final types do not yet exist, and every new fake/Pg factory stub that returns an error is executable application/adapters code that lowers the strict 100% gate unless a behavioral test reaches and asserts that branch. Main pre-wiring also promises only publisher/video loops even though 5.4 says its LLM flags and composition already exist.

FIX: In 5.0, define the final public contracts and typed unavailable result, provide compiling placeholder implementations for every future entry point, and add behavior-asserting tests for every placeholder factory/router/config branch. Pre-wire the final publisher, video, draft-engine, renderer, and moderation compositions with explicit disabled/unavailable behavior and startup config tests; then require 100% coverage before releasing the wave.

[B3] — `PublishDueDrafts` cannot set publication state “in the same tx” while calling the existing use cases: `SeedMarket` and `AdvanceMarket` each open and commit their own transaction. A crash can therefore leave a seeded market, live market, jobs, and draft status at different stages. Worse, `SeedMarket` replay returns the caller-supplied market id rather than loading the id stored by the idempotency record, so racing sweeps that generate different market UUIDs can replay success and then try to advance a nonexistent market.

FIX: Specify publication as an explicitly crash-recoverable saga. Persist or deterministically derive `published_market_id` before the first call, serialize/claim the draft row, use stable `draft:<id>:seed` and `draft:<id>:golive` keys and independently idempotent job facts, and mark `published` only after all prior stages are observable; every retry and `publish_now` must enter this same authority. Test crashes after claim, seed, go-live, each job enqueue, and final draft update, plus sweep/sweep and sweep/publish-now races.

[B4] — The job schema cannot implement the claimed two-worker and crash-replay semantics. `status` plus `updated_at` provides neither a fencing token nor an unambiguous lease/due time; holding a row lock while rendering makes a network/filesystem operation part of a long database transaction, while committing `rendering` without a lease can strand a job forever. A stale crashed worker can also overwrite a newer attempt, and no partial unique index actually enforces the active-job rule.

FIX: Add `available_at`, `claim_token`, and `lease_expires_at`; claim a bounded batch in a short `FOR UPDATE SKIP LOCKED` transaction, increment attempts and commit before rendering, then complete with a compare-and-set on `(id, claim_token, status='rendering')`. Reclaim only expired leases and pin saturating backoff math/max-attempt boundaries. Add the partial unique index with its exact active statuses in 0007 and test two claimers, crashes before/after render, expired recovery, stale completion, retry timing, and terminal failure.

[B5] — The persistence model cannot represent the promised artifacts or hot swap. Neither migration 0007 nor the current market schema adds poster/video references, and current market rows, REST DTOs, `MarketSnapshot`, and v1 WS frames carry none. A client reconnecting after attachment therefore cannot rehydrate the asset. In addition, “unique active per `(market, kind)`” collapses every user's `share_card` for one market because `video_jobs` has no user/cache/spec identity.

FIX: Model poster and video references separately (or add a typed current-asset projection), migrate their durable relationship, and pre-wire them through Pg rows, market REST/list/detail DTOs, snapshots, and a versioned `VideoAttached` frame with `outbox_seq`, job id, kind, and asset ref. Define the pre-attachment placeholder and reconnect semantics. Give share cards an owner/cache key or render them outside the market-kind uniqueness domain; include realization/version identity so cached PnL cannot be served to the wrong user.

[B6] — The LLM moderation design targets an “existing `Screen` seam” that does not exist: Phase 4 exposes a domain `Screen` enum/function, and `PostComment` invokes it inside the transaction after acquiring guard, user, market, and parent locks. Implementing a remote adapter there would either require changing files frozen from all wave owners or hold database locks across network I/O. The only-escalate rule is also unsafe if delegated to the adapter that returns the second verdict.

FIX: In 5.0, introduce an application-owned moderation port and composition policy. Run the optional remote preflight outside the locked transaction, rerun the deterministic screen on the exact submitted body in the transaction, and combine results with an application-enforced severity join so deterministic `Shadow`/`Blocked` can never become less strict; pin whether the LLM may return `Blocked` or only `Shadow`. Disabled/unavailable remote moderation must preserve deterministic behavior, not fail comment posting.

[M1] — “Tests pass and coverage stays 100%” is insufficient proof that the 7,000-plus-line split is a pure move: tests or source lines can disappear while the resulting ratio remains 100%, and visibility/re-export changes can silently alter the public surface. More critically, the workers cannot safely run the stated full gates concurrently: `just coverage` performs workspace-wide clean/instrumentation against shared targets, global compilation observes other workers' incomplete files, and Pg processes can share the same database even if each process uses one test thread.

FIX: Make the pure split a separately completed logical checkpoint before any new behavior, recording identical test inventory/count, coverage numerator and denominator per crate, and a normalized symbol/source manifest before and after. During the wave use isolated target/LLVM directories and per-worker databases for local tests, prohibit workspace coverage clean while peers run, and serialize authoritative workspace fmt/clippy/test/coverage/deps gates at coordinator barriers.

[M2] — Slotting and draft expiry are under-specified at the boundaries. “Next boundary” does not say whether an exact cadence boundary is returned or skipped; `daily_slots: u8` does not generally divide 86,400, so “evenly-spaced UTC times” needs a pinned rounding formula. Independent approvals all selecting the same next slot do not enforce a daily/hourly supply cadence. Computing TTL from mutable startup config also changes old drafts' expiry, and count-then-insert backpressure lets concurrent creators exceed `max_pending_drafts`.

FIX: Pin strict/inclusive behavior, integer UTC slot arithmetic (including non-divisors, pre-epoch input, and overflow), total ordering, and a database uniqueness/capacity rule that reserves the next unoccupied tier slot. Persist `expires_at` at creation, define `now >= expires_at` and approve/expire row-lock races, and serialize capacity admission with an advisory/counter lock or database-enforced token. Test cadence rollover, every exact boundary, concurrent approvals/creates, config restart, and expiry versus review.

[M3] — `RenderSpec` is not constrained enough to guarantee byte-identical SVG. Palette tokens, “layout constants,” pinned fonts, and no timestamps do not control hash-map iteration, float formatting, locale/number formatting, Unicode normalization, escaping, text measurement/wrapping, attribute order, line endings, dependency versions, or font fallback. Equality from two calls in one process would miss several of those sources.

FIX: Define a versioned, fully ordered spec using integer/fixed-point geometry, literal palette values, embedded font bytes plus hash, deterministic normalization/escaping/wrapping/measurement, explicit numeric formatting, attribute order, and newline rules. Golden tests must assert exact bytes and a pinned digest for adversarial Unicode/long text and repeated fresh renderer instances; run the same vectors in Rust and any alternate renderer, and reject unavailable fonts rather than falling back.

[M4] — Artifact persistence/serving has no crash or path-safety contract. If the worker writes the final filename directly, a crash can leave a partial SVG that a `ready` retry or immutable cache exposes. If `asset_url` or a renderer-supplied path is joined to `render_dir`, `GET /assets/{job_id}.svg` can become a traversal or symlink escape despite its UUID-looking route.

FIX: Derive the filename solely from validated UUID/job kind, write a private temp file, flush and atomically rename within a canonicalized render root, then transition to `ready`; never open a database/user-supplied path. Resolve the job by id/status before serving, reject symlink/root escapes, set SVG content type plus `nosniff`, and apply immutable caching only to finalized content-addressed/versioned artifacts. Test partial writes, rename/DB crash points, traversal encodings, symlinks, unknown/non-ready jobs, and retry byte identity.

[M5] — The LLM test/gating story is too weak to prove no-network or injection posture. Grepping for two spellings does not prevent another HTTP client or host; a fixture output saying an attack is harmless proves only the fixture, not that the outbound request preserved the versioned system/data boundary. The construction rule also leaves half-configured credentials, malformed base URLs, and runtime fallback behavior unspecified.

FIX: Make transport injection mandatory and confine the only real-network constructor to one audited module; tests receive a deny/panic transport and assert the exact outbound method, URL, headers-with-redacted-secret, prompt version, JSON schema, delimiters, and comment bytes before returning handwritten fixtures. Construction must validate key/base URL as an all-or-none pair and return a typed unavailable/config error before building a client. Put fallback choice and the moderation severity join in application code and cover absent, partial, malformed, refusal, schema-invalid, over-limit, and injection-shaped cases.

CHECKPOINTS 1-8:

1. **Split safety:** Not yet proven. The test/coverage ratio can stay green after deletions, and the proposed split changes module privacy/re-exports; B2 and M1 require a compiling final skeleton plus invariant test/source/symbol inventories before new behavior lands.
2. **Ownership matrix:** Not complete. B1 enumerates the missing shared manifests, crate roots, Pg/fake state, errors/models, WS/relay, OpenAPI, fixtures/assets, and gate files; it also identifies direct 5.1/5.2/5.4 conflicts. These must be assigned and frozen in 5.0.
3. **Publication idempotency:** Not sound as written. Stable keys are necessary but insufficient because the existing use cases own separate transactions and replay can echo a different caller-supplied UUID. B3's persisted/deterministic market id and staged saga make sweep/sweep and sweep/publish-now convergence testable.
4. **Job worker:** Not implementable from migration 0007. Two workers require short claims, leases and fencing, deterministic backoff, compare-and-set completion, and a real partial unique constraint as specified in B4; rendering under a database row lock is not acceptable.
5. **Renderer determinism:** The goal is correct, but the current spec controls too few byte-producing decisions. M3's integer, ordered, versioned representation and exact golden bytes/digest are the minimum credible proof.
6. **LLM adapters:** Construction-time gating and handwritten fixtures are appropriate foundations, but the present grep and response-only fixtures are not airtight. B6/M5 require transport confinement, exact request-shape assertions, an application-enforced severity join, and remote work outside the comment lock transaction.
7. **Hot-swap:** Not coherent yet. B5 requires durable poster/video references on both live snapshots and update frames, explicit placeholder/reconnect behavior, and a share-card identity distinct from `(market, kind)`.
8. **No-VCS parallel discipline:** No VCS operation is requested, but zero overlapping named files does not make concurrent workspace gates safe. B1/M1 require an exhaustive ownership map, isolated worker build/test state, and coordinator-serialized global gates; only then is the four-worker wave believable end to end.
