VERDICT: fix-first
1. [B1] — PLAN.md Task 2 / spec §5.6: Requiring every account to stay non-negative makes the stated production deposit credit “from an escrow account” impossible from genesis and likewise requires an unstated pre-funded source for external withdrawals/fees, so the ledger boundary is not yet representable. FIX: Specify asset/liability/equity account semantics and signed normal balances, or model deposits/withdrawals as balanced user-liability versus treasury-asset transactions with explicit genesis capitalization and per-account lower-bound policy rather than a universal zero bound.
2. [B2] — PLAN.md Task 0 / coverage commands: The proposed stable toolchain command `cargo llvm-cov ... --branch --fail-under-branches 100` is not runnable because current cargo-llvm-cov marks branch coverage nightly-only and exposes no `--fail-under-branches` option. FIX: Pin a tested nightly plus a supported report-parsing branch gate, or replace the promise/command with supported line/region thresholds and a separate explicit branch-check script.
3. [M1] — PLAN.md Task 3 / sell quadratic: Although the smaller real root is the valid root, `b*b`, `4*s*no`, and buy `yes*no` overflow signed i128 for valid positive i64 inputs, while `isqrt_u128` conflicts with the “all intermediates i128” prescription. FIX: Define checked u128 arithmetic for nonnegative products/discriminants (or cap every public input/reserve below a proven bound), convert only after range checks, and property-test near i64::MAX.
4. [M2] — PLAN.md Task 6 / settlement: `settle_market` cannot generally satisfy conservation when `escrow` is “total minted collateral” because its input includes only user positions and omits pool outcome reserves/LP holdings; ordinary unsold inventory therefore yields a large remainder mislabeled dust. FIX: Settle every outstanding outcome balance, including pool/house inventory, or define escrow as exactly the collateral backing the supplied positions and test the actual mint/trade state.
5. [M3] — PLAN.md Task 7 / schema v1: The ER contract has no unique outcome identity within a market, no FK-level proof that votes/outcomes and pool_reserves/outcomes belong to the same market, no nonnegative reserve/position checks, and no trade-to-market key despite calling trade `seq` per-market. FIX: Add `unique(market_id,idx)`, composite market/outcome constraints or remove redundant market_id, positive/nonnegative checks, and market_id plus `unique(market_id,seq)` on trades.
6. [M4] — PLAN.md Task 7 / vote sequencing: `unique(market_id,seq)` only detects races; without an allocation protocol concurrent casts collide and retries can change visible numbering. FIX: Specify a locked per-market counter updated atomically in the same transaction as an idempotent vote insert, and add a command/idempotency key so network retries cannot create ambiguous results.
7. [M5] — PLAN.md Task 7 / ledger enforcement: Deferring the database sum-zero constraint while Phase 0 creates a shared schema lets any SQLx/Python path bypass the only money invariant, and SQL CHECK cannot enforce a cross-row transaction sum as spec §5.6 implies. FIX: Add a deferred constraint trigger before any write adapter is accepted, and require the adapter transaction to insert the header/entries and validate all affected accounts atomically.
8. [M6] — PLAN.md Task 0 / CI and tool bootstrap: `just ci` is not a local mirror of CI because neither local bootstrap nor CI installs `just`/cargo-mutants, CI has no mutation job or ≥90% calculation, `cargo deny` runs only via an action rather than `just ci`, and `cargo audit` promised by spec §5.5 is absent. FIX: Pin/install every tool, add deny/audit to the local and hosted pipelines, and implement an explicit killed/(killed+missed) ≥90% gate instead of relying on cargo-mutants’ all-or-any exit code.
9. [M7] — PLAN.md Task 6 / dust bound: The stated `dust < positions.len()+2` is loose and not the mathematical contract; for P nonnegative payouts each floor loses <1 micro, so integer dust is 0..P-1 only when escrow equals the exact unfloored total, otherwise “dust” can be arbitrary. FIX: Define `escrow = floor(sum(exact claims))` (or include all claims whose exact sum is integral), enforce `0 <= dust < P`, and test P=0/1 plus maximal fractional residues.
10. [m1] — PLAN.md Task 0 / justfile: Recipes written as `fmt: ; cargo ...` put no indented body after the recipe header and are not valid documented just syntax. FIX: Put each shell command on the following indented line and validate with a pinned `just --fmt --check`/dry run.
11. [m2] — PLAN.md Task 3 / rounding checkpoint: Fee-ceil and retained-reserve-ceil are each individually safe but can compound by nearly two micro-units of user value (for example y=n=2, gross=101, 1% fee), contradicting the “by 1 micro-unit” wording. FIX: Document that the bound is <1 micro per independent rounding operation (<2 on a buy before price valuation), and test economically valued round trips rather than claiming a single-unit aggregate bound.
12. [m3] — PLAN.md Tasks 5–6 / integer coverage: Scoring conversions and the exact-50.00% tie arithmetic check out, and redemptions sum to 1,000,000 exactly with payout floor; however the “outward guesses” monotonic proptest is underspecified at domain edges and can accidentally change majority context. FIX: Generate two valid guesses with ordered absolute distance from one fixed actual and assert only accuracy monotonicity, keeping separate boundary tests for the documented both-sides-win tie.
13. [m4] — PLAN.md Task 7 + spec §10.3 / agent audit growth: `agent_steps` stores two full JSON states plus rendered prompt/raw output indefinitely, yet the schema has neither retention/partitioning nor indexes supporting run chronology/retention deletion, and inbound-message dedupe is absent. FIX: Add indexes on `agent_steps(run_id,seq)` (the unique suffices for reads), `agent_runs(started_at)`/user-thread chronology, a unique channel+inbound_msg_id dedupe key, and an explicit partition/retention/redaction policy before recording every run.
CHECKPOINTS:
1. The smaller sell root is always the only root in [0,min(no,yes+s)); floor-isqrt makes the candidate no larger than the exact root and the decrement guard restores k>=old k, while `c >= no` is the correct mathematical drain guard (c=no-1 leaves one unit and is valid), subject to fixing overflow and using a checked loop.
2. Charging the same percentage after the sell curve is coherent with a symmetric ~1% fee on user cash flow, although “matches observed  behavior” remains unverified product evidence rather than a mathematical conclusion.
3. Fee ceil, retained-reserve ceil, and payout floor all favor the pool; each error is <1 unit in its own quantity, but fee+reserve rounding can exceed one micro in aggregate and must be disclosed/tested as separate operations.
4. Awarding both sides the majority component at exactly 50.00% is internally consistent and avoids arbitrary tie-breaking; keep it only if “winning side” copy explicitly defines a tie as both sides, otherwise awarding neither better matches the published term.
5. Universal non-negativity is sound for custodial subaccounts only after explicit external/genesis funding semantics exist; as written deposits are unrepresentable, while seed/reversal/withdrawal are representable only when every source account is pre-funded and reversals cannot exceed the original credited amount.
6. App-only sum-zero is not acceptable once write adapters exist; implement the deferred trigger in Phase 1 before accepting money writes, and solve vote sequence concurrency now with an atomic locked counter plus idempotent cast semantics.
7. `build_graph(router=...)` is a good model seam for the router skeleton, but later extractors/composer need the same typed injectable runnable interface; also change `Callable` to an async protocol and avoid coupling nodes directly to provider-specific structured-output APIs.
