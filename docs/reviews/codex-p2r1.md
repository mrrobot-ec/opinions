CHECKPOINTS:
1. Relay correctness — `SKIP LOCKED` prevents simultaneous claims only while the transaction is live; broadcast-then-mark is at-least-once with a duplicate window, which is acceptable for state frames and tape only with explicit `(seq, kind)` client dedupe, currently unstated.
2. WS backpressure — disconnecting a lagged receiver is the correct bounded-memory policy, but the web client needs specified reconnect/backoff and state rehydration or cursor replay before this is complete.
3. Scheduler races — row/advisory locks prevent simultaneous mutation, but current `AdvanceMarket` has no durable replay record and the stable key alone turns the loser into `IllegalTransition`; failed attempts remain retryable because their transaction rolls back.
4. Integrity-rule ordering — accepted-vote replay should short-circuit before later velocity/age rules, and `now >= closes_at - near_close` correctly makes the exact threshold inclusive, but “at-limit passes” must mean pre-count `max-1` because pre-count `max` is rejected by the stated `>=` rule.
5. Chart math — `price_yes = 1_000_000 - price_no` is the correct NO normalization, but all price/weight/volume intermediates need `numeric`, checked narrowing, an explicit weighting definition, and nonzero bucket validation.
6. PWA scope honesty — server-sourced quote/price numbers keep money math in Rust and a labeled loopback dev identity is acceptable, but a token placed in localStorage is not “server-side only” and must be documented as local-demo exposure or replaced by a server proxy.
7. No-VCS discipline — the Phase 2 task steps contain no required VCS command and the generation scripts do not invoke Git, but `gen_openapi.sh` still describes a “CI git-diff” and reproducibility should be specified as two runs with digest/`cmp` equality rather than an implicit repository diff.
