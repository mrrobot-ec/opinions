NEW FINDINGS:

[B1] — PLAN.md Task 2 `Balances::apply`: The prescribed scratch-vector pass computes each repeated account entry from the same old balance, so a balanced transaction such as A:-7, A:-6, B:+13 applied to A=10/B=0 can finish at A=4/B=13 and create 7 units. FIX: Aggregate all entries by AccountId with checked arithmetic before validation/write (or reject duplicate accounts), then property-test arbitrary multi-entry transactions with repeated accounts and assert total conservation plus atomicity.
2. [B2] — PLAN.md Tasks 2/7 + spec §5.6: `Transaction::new` balances one scalar while domain accounts have no Currency, so a transaction can debit `usdc_credit` and credit withdrawable `usdc`, and multiple External rows also defeat the singular contra invariant. FIX: Add Currency to the domain account model, require every transaction to balance per currency (model credit conversion as funded four-leg per-currency-balanced entries), enforce one External account per currency in domain/DDL, and reconcile/assert invariants per currency.
3. [B3] — PLAN.md Tasks 7–8 / spec §7.5 single-flight: The pending-action index is non-unique and “single-flight lock per thread” has no cross-process locking or atomic consume protocol, so two service replicas can create multiple active previews or race distinct confirms against an ambiguous pending row. FIX: Specify a distributed per-thread transaction/advisory lock, a unique-active-action constraint, `UPDATE ... WHERE consumed_at IS NULL AND expires_at>now() RETURNING` consumption, and concurrent multi-replica tests proving exactly one preview/execute.

[M1] — PLAN.md Task 3 input bounds/tests: With y=n=`MAX_RESERVE` and c=`MAX_AMOUNT`, a valid YES buy makes `no'` nearly `2*MAX_RESERVE`, and a large valid sell can likewise make `yes' > MAX_RESERVE`; additionally `sell_cannot_drain_pool` excludes the newly required `InputTooLarge`, while an unrestricted `x*x`/`x*x-1` isqrt generator can overflow/underflow in the test itself. FIX: Define caps closed under state transitions by rejecting any quote whose resulting reserve exceeds the state cap (or use separate proven state/order caps), update expected errors, and bound square tests to `x in 1..=u64::MAX` plus a separate x=0 case.
