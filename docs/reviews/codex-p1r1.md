[B1] — docs/plans/phase1-core-write-path.md Tasks 1.1–1.3, `LedgerWriter::ledger_apply`: The port and adapter protocol never lock touched ledger accounts or validate their derived post-balances, while migration 0002 checks only per-currency zero sums, so two concurrent spends can both commit and drive an internal account negative. FIX: Add a transaction-only `market_for_update` (or status-guarded atomic update) and require lock acquisition plus clock/cutoff validation in a documented order before pool, vote-counter, or resolution writes, with concurrent cutoff/transition tests.

[B3] — docs/plans/phase1-core-write-path.md Tasks 1.1–1.3, idempotency: The check-then-insert protocol is not race-safe because a concurrent unique violation leaves the PostgreSQL transaction aborted, so mapping it to `DuplicateKey` cannot then load and return the original receipt within the promised single `*Tx`. FIX: Serialize each idempotency key before the first read (for example with a transaction-scoped advisory lock or reservation table), then read-or-create, and test simultaneous identical trade, vote, resolve, and deposit requests returning one committed result without counter/reserve drift.

CHECKPOINTS:
1. Transaction boundaries — NOT SOUND: pool-row locking is useful, but lifecycle/cutoff checks and account balance validation are outside a complete locking protocol (B1–B2).
2. ISP honesty — PARTIAL: the role traits are small and `TradeTx` legitimately composes the roles PlaceTrade needs, but `Store` is a god factory/query bound; split it into per-use-case transaction factories plus narrow query traits.
3. Idempotency semantics — NOT RACE-SAFE: an early lookup plus unique-violation mapping cannot recover the original inside an aborted PostgreSQL transaction; serialize the key before lookup (B3).
4. Trigger SQL — INSERT PATH SOUND WITH GAPS: deferred per-currency sums, nonempty headers, and append-only entries work as stated for one or many currencies, but account identity/currency mutation can bypass the historical invariant and must be closed (M1).
5. Ledger mapping — ALGEBRAICALLY BALANCED BUT INCOMPLETE: BUY, SELL, PAYOUT, SEED, and DEPOSIT legs sum to zero and SELL cannot exhaust correctly tracked complete-set escrow, but this depends on ownership/account locks; the exact pre-resolution invariant is `escrow micro-USD == pool reserve + all non-pool holdings` separately for YES and NO, not an undefined “pool value,” and settlement needs B4's zero-leg handling.
6. OpenAPI freshness — NOT SOUND: a deterministic offline exporter, exact generator pin, no-timestamp/sorted output, and diff checks for both Rust OpenAPI and Python models are required (M6).
7. Coverage mechanics — ACHIEVABLE: with cargo-llvm-cov 0.8.7, `-p application` and `-p adapters` scope reports to those packages and the CI PostgreSQL service/migration lets DB tests count, provided every coverage invocation receives `DATABASE_URL` and the SQLx tool is exactly pinned.
8. E2E honesty — NOT YET: the lexical pre-router gate and malicious-router test are the right proof shape, but memory-backed production wiring plus missing identity/extraction paths currently prevent the demo from proving the real corridor (B6).
